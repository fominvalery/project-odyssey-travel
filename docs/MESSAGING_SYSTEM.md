# Система сообщений Кабинет-24

Документ описывает работу обоих каналов сообщений: чат по объектам из маркетплейса
и личная переписка между участниками Клуба. При изменении кода — обновляй документ.

## 1. Архитектура — два канала, одна страница

| Канал | Кто пишет | Где хранится | Где видно |
|---|---|---|---|
| **Чат объекта** (маркетплейс) | Любой посетитель (анонимно) | `object_chat_messages` | «Сообщения» в дашборде владельца + модалка в маркетплейсе |
| **Личка Клуба** | Только участники Клуба | `messages` | «Сообщения» в дашборде |

Страница `/dashboard → Сообщения` **объединяет оба канала** в один список с разными иконками:
- Object-чат: 🏠 синий градиент, заголовок «Имя · Название объекта»
- Клуб: фиолетовый, обычные ФИО + аватар

## 2. Сценарий: клиент пишет из маркетплейса

```
Посетитель открывает карточку объекта в маркетплейсе
        ↓
Нажимает «Написать», вводит имя + телефон + текст
        ↓
POST /object-chat (sender='client')
        ↓
1. INSERT в object_chat_messages (owner_id подтягивается из objects.user_id)
2. Если первое сообщение → INSERT в leads (source='Чат объекта')
3. INSERT в notifications (тип 'object_chat') — для колокольчика владельца
4. SMTP email владельцу с кнопкой «Ответить в кабинете»
        ↓
Владелец видит:
  • Бейдж 🔔 в колокольчике (+1)
  • Письмо в почте с контактами
  • Новый диалог в /dashboard → Сообщения (иконка 🏠)
```

### Когда повторное сообщение от того же клиента
- INSERT нового сообщения (тот же session_id)
- Лид **НЕ создаётся** повторно
- Уведомление и email **создаются** для каждого сообщения

## 3. Сценарий: владелец отвечает

```
Владелец открывает диалог в /dashboard → Сообщения
        ↓
Пишет ответ
        ↓
POST /object-chat (sender='owner', owner_id, object_id, session_id)
        ↓
INSERT в object_chat_messages с sender='owner', is_read=TRUE
        ↓
Клиент видит ответ в модалке маркетплейса (компонент пуллит каждые N секунд)
```

При открытии диалога владельцем:
```
PUT /object-chat {owner_id, object_id, session_id}
        ↓
UPDATE object_chat_messages SET is_read=TRUE
WHERE owner_id=? AND object_id=? AND session_id=? AND sender='client'
        ↓
Счётчик непрочитанных уменьшается
```

## 4. Структура БД

### `object_chat_messages`
| Колонка | Тип | Описание |
|---|---|---|
| `id` | UUID | PK |
| `object_id` | TEXT | ID объекта |
| `session_id` | TEXT | UUID клиентской сессии (localStorage) |
| `sender` | TEXT | `'client'` или `'owner'` |
| `name` | TEXT | Имя клиента (только для client) |
| `phone` | TEXT | Телефон клиента |
| `text` | TEXT | Сообщение |
| `owner_id` | UUID | ID владельца объекта (для быстрых запросов) |
| `is_read` | BOOLEAN | Прочитано ли владельцем |
| `created_at` | TIMESTAMPTZ | Время |

**Индексы:**
- `idx_ocm_owner` (owner_id)
- `idx_ocm_object_session` (object_id, session_id)
- `idx_ocm_unread_owner` partial WHERE is_read=FALSE

### `messages` — личка Клуба
- `id`, `sender_id`, `receiver_id` (UUID), `text`, `is_read`, `created_at`
- UNIQUE по `referrals.referred_id` гарантирует одного реферера

### `notifications` — колокольчик
- `id`, `user_id`, `type`, `title`, `body`, `read`, `created_at`
- Тип `'object_chat'` для уведомлений о сообщениях из маркетплейса

## 5. Backend endpoints

### `/object-chat`
| Метод | Параметры | Описание |
|---|---|---|
| GET | `?object_id=&session_id=` | Сообщения чата (для клиента/владельца) |
| GET | `?owner_id=&dialogs=1` | Список всех диалогов владельца |
| GET | `?owner_id=&unread_count=1` | Счётчик непрочитанных |
| POST | `{object_id, session_id, sender, text, name?, phone?, owner_id?}` | Отправить сообщение |
| PUT | `{owner_id, object_id, session_id}` | Пометить как прочитанное |

### `/auth?action=chat`
| chat_action | Метод | Описание |
|---|---|---|
| `dialogs` | GET | Объединённый список (Клуб + объекты) |
| `messages` | GET | Сообщения конкретного диалога Клуба |
| `unread_count` | GET | Общий счётчик: `club_count + object_count` |
| `send` | POST | Отправить личное сообщение (Клуб) |
| `read` | POST | Пометить переписку прочитанной |

### Поллинг
- Диалоги и сообщения обновляются каждые **30 секунд**
- Колокольчик показывает суммарный unread (Клуб + объекты)

## 7. Email-уведомление

Используется `SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASSWORD` из секретов.
Шаблон письма владельцу:
- Тема: `[Кабинет-24] Сообщение по объекту «...»`
- HTML с контактами клиента и кнопкой «Ответить в кабинете» → `SITE_URL/dashboard?tab=messages`

При отсутствии SMTP-секретов email тихо пропускается, остальная логика работает.

## 8. Чек-лист ручной проверки

1. **Анонимный клиент** заходит на карточку объекта в маркетплейсе → пишет с именем и телефоном
2. У **владельца**:
   - +1 в колокольчике
   - Email на почту с контактами
   - Новый диалог в `/dashboard → Сообщения` с иконкой 🏠
3. **Владелец отвечает** в дашборде → клиент видит ответ в модалке маркетплейса
4. **Лид создан** в CRM (только первое сообщение)
5. **Повторное сообщение** клиента → второе уведомление, лид НЕ дублируется
6. **Открытие диалога** владельцем → счётчик непрочитанных обнуляется
7. **Личка между двумя брокерами Клуба** работает как раньше (раздел «Сеть» → «Написать»)
8. Оба типа диалогов **в одном списке**, сортируются по времени

## 9. Известные ограничения

1. **Анонимный клиент** не получает email-уведомления о ответе (только видит в модалке если откроет)
2. **Push-уведомления в браузере** не реализованы — только колокольчик при перезагрузке + поллинг
3. **Звуковое уведомление** не реализовано
4. **Файлы и фото** в чате не поддерживаются — только текст
5. **Удаление сообщений** не реализовано
