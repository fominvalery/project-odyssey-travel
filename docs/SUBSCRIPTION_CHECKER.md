# Subscription Checker — Проверка подписок и оповещения

Функция `/backend/subscription-checker` — критически важный фоновый процесс.
Запускается платформой poehali.dev автоматически **раз в сутки**.

Отвечает за:
1. Уведомления пользователям о предстоящем окончании подписки Клуб
2. Сброс тарифа на Basic при истечении grace period
3. Автоуведомления и автопродление для суперадмина
4. Уведомления и автоснятие объявлений с истёкшим сроком

---

## 1. Жизненный цикл подписки Клуб

```
subscription_end_at         grace_period_end_at
        |                           |
  ──────●───────────────────────────●──────────►
    истекает                 grace (3 дня)    → Basic

  за 5 дней  → уведомление
  за 3 дня   → уведомление
  за 1 день  → уведомление
  день X     → уведомление "сегодня истекает"
  grace идёт → уведомление + осталось N дней
  grace истёк→ сброс на Basic + снятие объектов
```

---

## 2. Таблица оповещений (обычный пользователь)

| days_left | Колокольчик | Email | Действие |
|---|---|---|---|
| 5 | ✅ «истекает через 5 дней» | ✅ | — |
| 3 | ✅ «истекает через 3 дня» | ✅ | — |
| 4 | ✅ «истекает через 4 дня» | ✅ | — |
| 2 | ✅ «истекает через 2 дня» | ✅ | — |
| 1 | ✅ «истекает завтра» | ✅ | — |
| 0 | ✅ «истекает сегодня» | ✅ | — |
| <0, grace идёт | ✅ «истекла, осталось N дн.» | ✅ | — |
| grace истёк | ✅ «деактивирована» | ✅ | Сброс на Basic + объекты |

---

## 3. Суперадмин (владелец платформы)

Суперадмин **исключён из обычного цикла** (`is_superadmin = false` в основном запросе).
Для него отдельный блок с особой логикой:

| days_left | Колокольчик | Email | Действие |
|---|---|---|---|
| 5 | ✅ [Система] | ✅ | — |
| 3 | ✅ [Система] | ✅ | — |
| 0 | ✅ [Система] продлена | ✅ | **Автопродление на 30 дней** |

Тема письма начинается с `[Кабинет-24]` — легко найти в почте.
Суперадмин **никогда не слетает на Basic**.

---

## 4. Жизненный цикл объявления

```
expires_at - 3 дня  → уведомление «истекает через 3 дня» (1 раз)
expires_at           → auto_unpublished = TRUE, published = FALSE + уведомление
```

Флаг `expiry_notified_at` на объекте — защита от дублирования уведомлений.

---

## 5. Структура ответа функции

```json
{
  "ok": true,
  "results": {
    "notified_4d": 0,       // уведомлено за 2-5 дней
    "notified_2d": 0,       // (счётчик общий для 2,3,5 дней)
    "notified_1d": 0,       // уведомлено за 1 день
    "notified_expired": 0,  // уведомлено: истекло + сегодня
    "downgraded": 0,        // переведено на Basic
    "object_expiring_soon": 0,    // объявлений с уведомлением
    "object_auto_unpublished": 0  // объявлений снято
  }
}
```

---

## 6. Email (SMTP)

Использует `smtp.gmail.com:587` + STARTTLS.
Секреты: `SMTP_USER`, `SMTP_PASSWORD`.
При отсутствии секретов — email тихо пропускается, уведомления в колокольчик всё равно создаются.

---

## 7. Что проверять при изменениях

**Обязательно перед деплоем:**
- [ ] Тест возвращает 200 + `{"ok": true}`
- [ ] Поле `results` присутствует в ответе
- [ ] Суперадмин не попадает в основной цикл downgrade
- [ ] Автопродление суперадмина не создаёт дубликаты

**Проверить вручную после деплоя:**
- [ ] Запустить функцию вручную (GET /)
- [ ] Проверить колокольчик у пользователя с истекающей подпиской
- [ ] Проверить что письмо пришло на почту

---

## 8. Известные ограничения

1. Функция запускается **раз в сутки** — если день пропущен, уведомление не дублируется на следующий день
2. Нет защиты от двойного срабатывания уведомлений о подписке (в отличие от объявлений с `expiry_notified_at`)
3. Счётчики в `results` частично объединены (например `notified_2d` считает и 3 и 5 дней)
